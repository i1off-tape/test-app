## Решения

### Классификация статусов матчей
В фильтре реализованы 4 категории: «Все», «В игре», «Предстоящие» и «Завершённые»:
- **«В игре» (Live):** матчи со статусом `live` («Динамо : Рубин», 67'). Вынесены в отдельную вкладку, так как события в реальном времени требуют мгновенного фокуса болельщика и не должны смешиваться с расписанием будущих игр.
- **«Предстоящие»:** матчи со статусом `scheduled` (запланированные) и `postponed` (перенесённые, дата не определена). Эти матчи ещё предстоит сыграть.
- **«Завершённые»:** строго матчи со статусом `finished` с финальным счётом.
- **«Все»:** полный тур матчей.

### Неочевидные случаи в данных
1. **`startsAt: null` у перенесенного матча (`m7`):** попытка вызвать `new Date(null)` привела бы к отображению даты `01.01.1970`. Добавлена проверка на `null` и невалидную дату: для таких матчей выводится статус «Дата уточняется».
2. **Счёт `0:0` (матч `m2`):** в JavaScript число `0` является falsy-значением. Простая проверка `if (score?.home)` скрыла бы нулевой счет. Реализована строгая проверка `typeof score.home === 'number'`.
3. **Статус `live` с полем `minute` (`m4`):** карточка матча динамически дополняет статус текущей минутой («Идёт матч 67'») и выделяет бейдж акцентным цветом.
4. **Форматирование времени в часовом поясе устройства:** использован `Intl.DateTimeFormat` с локалью `ru-RU`, корректно отображающий время пользователя без привязки к фиксированному часовому поясу сервера.
5. **Плейсхолдер `OWNER/REPO` в `src/config.ts`:** шаблонный адрес возвращал 404. Адрес был скорректирован на актуальный репозиторий, а также реализована обработка сетевых ошибок с показом экрана ошибки и кнопки повтора.

## Баги из части 2

1. **Звёздочки:**
   - *Почему так происходило:* В функции `isFavorite` использовалась проверка `Boolean(favorites.indexOf(id))`. Для отсутствующего элемента `indexOf` возвращает `-1`, а `Boolean(-1)` в JavaScript равен `true`, из-за чего звёздочки считались активными у всех матчей сразу. При добавлении первого элемента он попадал на индекс 0, и `Boolean(0)` возвращал `false` (звезда гасла при добавлении). Кроме того, `toggle` мутировал массив по месту (`push`/`splice`) и передавал прежнюю ссылку в `setFavorites`, из-за чего React пропускал перерисовку компонентов.
   - *Что исправили:* Заменили проверку на `favorites.includes(id)`. В `toggle` применили функциональное обновление `setFavorites(prev => ...)`, возвращающее новый массив без мутаций.
2. **«Обновлено N сек назад»:**
   - *Почему так происходило:* В `useEffect` интервал был объявлен с пустым массивом зависимостей `[]` и выражением `setSeconds(seconds + 1)`. Из-за замыкания на начальное значение `seconds = 0` таймер каждую секунду вычислял `0 + 1` и застывал на числе `1`. Кроме того, отсутствовала очистка таймера через `clearInterval` и сброс при обновлении пропа `since`.
   - *Что исправили:* Секунды теперь вычисляются как реальная разница `Date.now() - since.getTime()`. Добавлена зависимость `[since]` для сброса при получении свежих данных и возвращается функция очистки `clearInterval`.

## Как я использовал ИИ

- Инструменты: Antigravity CLI с моделью Claude/Gemini, браузерный суб-агент `/browser` для UI-тестирования в реальном браузере.
- Проверка и корректировка работы агента:
  - Проверка верстки и взаимодействия на `http://localhost:8081` проводилась через вызов суб-агента `/browser`.
  - При первой генерации `MatchesScreen.tsx` агент вызвал функцию загрузки с синхронным `setLoading(true)` внутри `useEffect`. Это привело к ошибке линтера `react-hooks/set-state-in-effect`. Ошибка была выявлена запуском `npx expo lint` и устранена разделением логики на чистый `initialFetch` внутри эффекта и обработчик действий пользователя `loadMatches`.
